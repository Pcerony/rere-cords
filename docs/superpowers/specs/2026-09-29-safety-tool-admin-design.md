# 安全道具管理员页面设计

## 目标

新增独立的管理员网页，让预约人资料、预约日期、所借道具及数量在同一视图中清楚呈现，并能安全地处理预约状态。保留现有 GitHub Pages 与 Supabase 架构，不在浏览器使用 service-role/secret key。

## 管理员流程

- 管理员打开专用页面，以 Supabase Auth 邮箱和密码登录；页面不提供注册入口。
- 登录后默认按创建时间倒序查看预约，可按状态筛选。每条预约显示编号、姓名、课程、邮箱、领取日、归还截止日、道具名称与数量、申请状态。
- 管理员实地准备并放置道具、发送邮件后，将预约标为「已放置并通知」（`ready`）。也可取消预约；归还后标为「已归还」（`returned`）。状态操作前显示确认，完成后刷新记录及库存。
- 页面醒目提示：必须先实地放置并手动邮件通知，才可把状态标为已放置；系统不自动发送邮件。
- 退出登录后清除会话。未配置、未授权、网络错误及空列表均有明确状态。

## 安全与数据设计

- 新增 `reservation_admins` 私有 allowlist，以 Supabase Auth 的 `auth.uid()` 标识获准管理员。该表不向 `anon` 或 `authenticated` 直接开放读写。
- 提供固定 `search_path` 的 `SECURITY DEFINER` 管理员检查函数。预约、预约明细及库存的 SELECT RLS policy 仅对 allowlist 管理员通过；匿名访客继续只能使用现有库存与预约 RPC。
- 创建管理员状态变更 RPC，只允许 allowlist 管理员调用，且仅接受 `ready`、`cancelled`、`returned` 三种目标状态并更新时间戳。禁止管理员网页直接改表，避免客户端扩大写权限。
- 管理员通过 Supabase Dashboard 创建 Auth 用户，再用 SQL Editor 将该用户 UUID 加入 allowlist。须在中文设置指南中明确这些一次性设置步骤、后台 URL 与部署方式，以及不要共享管理员账号。
- 管理员网页复用现有公开 Supabase 配置及 supabase-js；未登录用户看不到任何预约资料。未经 allowlist 授权的已登录用户同样不得读取或更改预约。

## 页面范围

- 新建 `safety-tool-admin.html` 及对应脚本和样式，采用网站现有简洁视觉规范，桌面表格易扫描，窄屏使用可读的逐条布局。
- 支持登录、登出、状态筛选、重新载入和上述状态操作。道具 ID 映射为中文常用名称；预约时间以日本本地日期呈现。
- 不包含自动发信、管理员自助注册、库存调整、编辑参与者资料、批量操作或密码重置工作流。密码由 Supabase 管理员创建/重设。

## 验收与测试

- SQL/静态测试验证 allowlist 私有、预约信息只向 allowlist 管理员开放、状态 RPC 校验管理员与允许状态、匿名权限不扩大。
- 页面测试验证登录入口、预约字段与道具数量呈现、状态动作确认、无服务端凭证、异常状态和窄屏布局结构。
- 前端逻辑测试覆盖登录/登出、筛选、状态映射、RPC 错误不误报成功及成功后刷新数据。
- 中文文档涵盖创建管理员用户、授权 UUID、登录管理页、各状态的实际含义及手动邮件步骤。
- 本地运行全量 `npm test`。线上数据库迁移需管理员在 Supabase SQL Editor 执行后，再验证有效/无效管理员权限与一次状态变更；本地测试不声称代替线上验证。
