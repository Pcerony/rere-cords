# RERE-CORDS 提交入口与后续接收接口设计规格

日期：2026-07-31  
状态：实现前规格，等待书面复核

## 1. 背景

RERE-CORDS 当前是可直接部署到 GitHub Pages 等静态托管平台的单页网站。现有页面已经包含活动介绍、报名方法、制作日程和展览信息，但最终作品提交仍然依赖邮件说明，页面没有独立的“提交作品”入口。

本阶段不直接实现参与者表单、文件上传或 Google Drive 接收。先把主页入口、静态配置边界和内部接入说明准备好，确保后续可以接入 Google Apps Script、Google Drive 与 Google Sheets，而不会把尚未确定的参与规则写死在页面中。

## 2. 目标

1. 修复已经确认的网页问题：语言属性、时间线翻译、合作方图片替代文本和无障碍动画支持。
2. 在不引入服务器或构建系统的前提下，改善前端代码的可维护性、加载行为和滚动动画性能。
3. 在主页 `#apply` 报名方法之后、`#venue` 展览信息之前增加一个“提交作品”入口。
4. 让入口明确表达“最终提交通道即将开放”，避免参与者误以为当前已经可以在线上传。
5. 预留一个不含凭据的配置接口。未来只需要填入外部表单或 Apps Script Web App 地址，即可让入口指向接收页面。
6. 准备面向运营方的接入说明，但不提前决定最终参与表字段、文件类型、容量限制或审核规则。

## 3. 本阶段不做的内容

- 不制作参与者最终提交表单。
- 不实现文件选择、文件上传、Drive 写入、Sheets 写入或邮件通知。
- 不部署或调用 Google Apps Script，不在前端保存 Google 凭据。
- 不决定数字作品与实物作品的最终字段、附件数量、格式、大小和截止时间。
- 不把纸质参与表制作成下载链接；只有在运营方配置了真实文档地址后，页面才显示备用文档链接。
- 不改动当前报名阶段的邮箱递交规则；“报名方法”和未来的“提交作品”保持语义分离。

## 4. 页面入口设计

### 4.1 位置与信息层级

新增 `section#submission`，放在现有报名方法 `section#apply` 之后、展览信息 `section#venue` 之前。页面只增加一个主要入口，不在首屏增加新的主行动按钮，也不改变现有报名导航的优先级。

入口包含以下信息：

- 标题：提交作品。
- 简短说明：最终作品提交方式正在准备中；当前报名阶段仍按现有报名方法操作。
- 两个并列的路线摘要：数字/图片/数据作品，以及实物作品。这里只说明路线差异，不展示尚未确认的表单字段。
- 状态提示：提交通道即将开放。
- 一个未来可启用的提交按钮。当前禁用，不产生网络请求。
- 一个默认隐藏的备用文档链接。只有配置了合法地址后才显示。

数字作品和实物作品的摘要使用普通内容区块或列表呈现，不在页面中再嵌套装饰性卡片。入口的视觉语言沿用现有温暖的画廊风格、间距和字体层级。

### 4.2 多语言

新增入口的所有可见文案都加入现有 `zh`、`ja`、`en` 翻译表，并为每个 `data-i18n` 键提供三种语言。现有时间线第二步的 `time-step2` 也一并补齐，避免中文和英文切换后仍显示日文日期。

语言属性使用明确映射：中文为 `zh-CN`，日文为 `ja`，英文为 `en`。无效或缺失的本地存储语言值回退到当前默认语言（日文）。

## 5. 技术边界与配置接口

### 5.1 配置文件

新增独立的静态配置文件 `submission-config.js`，在 `app.js` 之前加载。默认配置如下：

```js
window.RERE_CORDS_SUBMISSION_CONFIG = {
    enabled: false,
    formUrl: "",
    fallbackDocumentUrl: ""
};
```

配置含义：

- `enabled`：是否显示可点击的外部提交入口，默认必须为 `false`。
- `formUrl`：未来的 Google Apps Script Web App 或其他外部接收页面地址。
- `fallbackDocumentUrl`：未来纸质参与表或备用说明文档的地址；为空时不渲染链接。

页面脚本使用安全默认值，即使配置文件缺失、字段不完整或地址不是 `http`/`https`，主页也必须正常加载。只有 `enabled === true` 且 `formUrl` 是合法外部地址时，提交按钮才转为可用链接。当前配置下不发起 fetch、iframe 请求或表单提交。

### 5.2 接入责任边界

静态网站只负责展示状态、提供入口和跳转地址。未来的 Apps Script 页面负责参与表内容、校验、文件接收、Drive 文件夹归档、Sheets 记录和成功编号。网站不直接连接 Drive API，也不包含服务账号、访问令牌或表格写入权限。

后续可采用外部页面跳转或嵌入式页面，但两种方式都遵循同一个 `formUrl` 配置边界。这样在没有服务器的情况下，网站仍可继续部署到静态托管平台。

Google 官方文档说明了 Apps Script Web App 的部署模型，以及 HTML Service 将表单和文件 Blob 传给服务器端函数的能力，后续实现接收端时以官方接口为准：

- [Apps Script Web Apps](https://developers.google.com/apps-script/guides/web)
- [HTML Service communication](https://developers.google.com/apps-script/guides/html/communication)

## 6. 后续内部接入文档

实现阶段新增 `docs/submission-integration.md`，内容限定为运营方和开发方使用：

1. 如何创建或选择 Drive 文件夹与 Sheets。
2. 如何部署 Apps Script Web App，并将公开访问地址填入 `submission-config.js`。
3. 如何在正式开放前完成一条测试提交、确认文件归档和表格记录。
4. 如何通过恢复 `enabled: false` 关闭入口并回退到备用说明文档。
5. 哪些规则必须在参与表字段确定后再补充。

该文档只描述接入步骤和配置合同，不虚构最终参与者要求，也不把测试地址写入生产配置。

## 7. 网页质量与性能修复范围

### 7.1 正确性和可维护性

- 补齐时间线第二步的翻译键，并做一次 HTML `data-i18n` 键与翻译表的完整性检查。
- 修正英文模式下的根节点 `lang` 属性。
- 根据素材实际内容修正合作方 Logo 的 `alt` 文本，避免把实验室 Logo 标为九州大学 Logo。
- 将提交入口的 DOM 选择器、状态更新和配置校验集中在明确的初始化函数中，避免把未来接收逻辑散落到滚动或语言切换代码中。
- 对语言值和外部地址做显式校验；翻译内容继续只来自本地受控字典。

### 7.2 无障碍与动效

- 增加 `prefers-reduced-motion: reduce` 样式，关闭平滑滚动、滚动出现位移和海报滚动动画的非必要动效。
- 动效关闭时，内容仍然立即可见，提交入口的状态和链接行为不改变。
- 保持现有图片的尺寸属性、可读替代文本、键盘焦点和按钮语义；禁用状态不能伪装成可提交状态。

### 7.3 性能

- 对滚动事件使用 passive listener，并用单个 `requestAnimationFrame` 批处理海报滚动效果，避免同一帧重复读取和写入布局。
- 缓存不会变化的 DOM 引用，避免初始化后反复查询相同节点。
- 确认没有使用中的图标库或脚本后移除死的 CDN 依赖，减少无意义的第三方请求。
- 保持图片懒加载、脚本加载顺序和静态部署兼容性；不引入新的运行时框架或打包步骤。

## 8. 验证标准

实现时先建立可重复的失败检查，再修改生产代码。最终至少验证以下内容：

1. `node --check app.js` 及新增脚本通过。
2. HTML 中所有本地资源引用存在，翻译键无缺失。
3. 默认配置下提交入口显示“即将开放”，按钮不可提交，页面没有对外部接收端的网络请求。
4. 填入测试格式的合法 `formUrl` 并开启配置后，入口只按预期变为外部链接；空地址或非法协议仍保持关闭。
5. 中文、日文、英文切换后，入口、时间线第二步和根节点 `lang` 都正确。
6. 桌面和窄屏浏览器中没有内容重叠、水平溢出或按钮文字被截断。
7. 开启 reduced motion 后，页面内容无需等待动画即可阅读。
8. 现有邮箱报名、海报灯箱、导航和展览信息不发生回归。

## 9. 发布与回退

本阶段发布后仍是纯静态网站，不依赖 Google 账号、服务器或外部接收服务。未来开放提交时，先在测试环境验证外部表单，再单独修改 `submission-config.js` 的三个配置值；若接收端出现问题，将 `enabled` 改回 `false` 即可隐藏可用入口，不需要回滚主页代码。

## 10. 明确决策

- 采用“主页预留入口 + 外部接收页面地址”的边界，不在本阶段制作实际提交表单。
- 默认关闭提交入口，避免在接收端尚未准备好时造成误提交。
- Google Drive、Sheets 和 Apps Script 只作为后续接收端，不进入当前静态页面的权限范围。
- 具体提交材料和参与表字段另立后续需求，不与本次主页修复混在一起。
